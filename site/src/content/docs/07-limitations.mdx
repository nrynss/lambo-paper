## 7.1 Multi-Repository Dispersion Effect

During 15,000 canonization cycles, the observed Swarm-policy Canonical count was zero. The Metal operational report records `gc_survived=0` for every concept, so the first gate already blocked promotion. The inverse-$R$ relationship below is a hypothesis about citation dilution, not an explanation of the observed zero or a proof of permanent promotion failure:
$$\mathbb{E}[\delta_r(c)] = \frac{\delta_{\text{base}}(c)}{R}$$

## 7.2 Text-Surface Affordance Gap

CUDA recorded 22 inspect misses in 82 calls. Metal recorded one miss in four calls, which is too small for a stable rate. The identifier-rendering explanation is a useful hypothesis. A controlled change that renders node IDs and compares exact-handle use is needed before attributing the misses to it.

## 7.3 Memory Compression on Unified Platforms

On the Metal rig, recall observations varied by idle-duration bin. Those bins do not establish an operating-system mechanism. Periodic lightweight touches are a proposed mitigation, not a demonstrated elimination of latency.


## 7.4 Controlled Retrieval Evaluation

A reproducible evaluation should hold memory contents, reader model, prompts, and token budgets constant. Compare flat-file, vector, and graph retrieval, then ablate graph expansion and invalidation handling. Publish questions, expected answers, grading criteria, repeated-run outputs, and retrieval latency alongside answer accuracy.

The [Metal deployment report](https://github.com/nrynss/lambo/issues/17) also records zero access counters, so frequency-based scoring had no recall-usage signal. Its zero GC-survival counts identify a first-gate eligibility problem to investigate before attributing promotion failure to repository dispersion.
