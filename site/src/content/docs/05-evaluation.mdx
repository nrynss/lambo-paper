We evaluated Lambo continuously during production development across two hardware rigs:
* **CUDA Production Rig:** AMD Ryzen 5 3600 CPU (6 cores, 12 threads), 78 GB DDR4 RAM, NVIDIA GeForce RTX 4070 SUPER GPU (12 GB dedicated VRAM), and CachyOS Linux kernel 7.2.2. The daemon runs as a systemd unit using the `candle-cuda` backend with BGE-M3 (1024 dimensions).
* **Metal Companion Rig:** Apple MacBook Pro with M3 Pro processor (12 CPU cores, 18 GPU cores), 18 GB Unified Memory, and macOS 15. The daemon runs under `launchd` using the `candle-metal` backend.

**Zero Infrastructure Faults vs. Tool Affordance Gap:**

## 5.2 Deduplication Dynamics: Swarms vs. Streams

Lambo evaluates semantic deduplication at write time. If an incoming concept matches an existing node with cosine similarity exceeding 0.92, the nodes merge.

  <p style="font-size: 0.875rem; color: #6b7280; margin-top: 0.5rem;">Figure 3: Empirical write-time deduplication rates across deployment regimes on Metal and CUDA.</p>

| Deployment Regime | Concepts Created | Concepts Matched | Deduplication Rate |
| :--- | :--- | :--- | :--- |
| **Metal: Review Swarm (Aug 19–23)** | 456 | 62 | **12.0%** |
| **Metal: Single-Agent Stream (Aug 24–Sep 4)** | 324 | 3 | **0.9%** |
| **Metal Rig Aggregate** | 780 | 65 | **7.7%** |
| **CUDA: Swarm-Named Agent IDs** | 309 | 14 | **4.3%** |
| **CUDA: Non-Swarm Agent IDs** | 1,285 | 22 | **1.7%** |
| **CUDA Rig Aggregate** | 1,594 | 36 | **2.2%** |

On the Metal rig, work followed a sharp temporal shift. During the multi-agent review swarm (J1-J3 tracks), multiple agents audited identical code changes simultaneously, yielding a 12.0% deduplication rate. In contrast, during single-agent development, deduplication dropped to 0.9%.

On the CUDA rig, development operated under continuous concurrency (five to 23 active agents daily). Swarm-named task agents matched at 4.3%, whereas non-swarm agents matched at 1.7%. This telemetry is consistent with the hypothesis that write-time deduplication correlates with concurrent task overlap rather than store consolidation.

| Model Group | Store | $n$ | Mean Length | Median (p50) | p90 | Share $>$500 B |

Across both independent stores, the Claude family generated verbose multi-sentence paragraphs (30% to 42% exceeding 500 bytes), whereas GPT and Grok agents generated concise atomic statements (fewer than 8% exceeding 500 bytes).

## 5.4 Coordination Telemetry: Advisory Locks vs. Receipts

Early agent memory designs proposed distributed advisory locks via `lambo_reserve`. Production telemetry showed that agents rarely acquired advisory locks:
* On the Metal rig, **zero calls** were made to `lambo_reserve` across 230 writes.
* On the CUDA rig, only **27 of 422 writes (6.4%)** utilized soft locks. Twenty-two of those 27 calls came from a single agent (`gpt-5.6-terra`), and only 5 of 63 agents ever invoked reservations.

This low adoption reflects discoverability hurdles and identifier fragmentation across 63 ephemeral identities rather than structural obsolescence. Instead, agents relied on the asynchronous write queue with monotonic receipts, which return in sub-millisecond time (0.1 ms median for derive) without synchronous blocking.
