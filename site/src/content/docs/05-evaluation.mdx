We observed Lambo during production development across two hardware rigs:
* **CUDA Production Rig:** AMD Ryzen 5 3600 CPU (6 cores, 12 threads), 78 GB DDR4 RAM, NVIDIA GeForce RTX 4070 SUPER GPU (12 GB dedicated VRAM), and CachyOS Linux kernel 7.2.2. The daemon runs as a systemd unit using the `candle-cuda` backend with BGE-M3 (1024 dimensions).
* **Metal Companion Rig:** Apple MacBook Pro with M3 Pro processor (12 CPU cores, 18 GPU cores), 18 GB Unified Memory, and macOS 26. The daemon runs under `launchd` using the `candle-metal` backend.

## 5.2 Deduplication Dynamics: Swarms vs. Streams

The inspected default configuration makes an incoming concept eligible for semantic matching at cosine similarity $\ge 0.85$. Frozen telemetry does not preserve every historical configuration override.

  <img src="/lambo-paper/fig3_dedup_regimes.png" alt="Deduplication Dynamics" style="max-width: 90%; border-radius: 8px; border: 1px solid #e5e7eb;" />
  <p style="font-size: 0.875rem; color: #6b7280; margin-top: 0.5rem;">Figure 3: Empirical write-time deduplication rates across deployment regimes on Metal and CUDA.</p>
</div>

| Deployment Regime | Concepts Created | Concepts Matched | Deduplication Rate |
| :--- | :--- | :--- | :--- |
| **Metal: Review Swarm (Aug 19–23)** | 456 | 62 | **12.0%** |
| **Metal: Single-Agent Stream (Aug 24–Sep 4)** | 376 | 3 | **0.8%** |
| **Metal Rig Aggregate** | 832 | 65 | **7.2%** |
| **CUDA: Swarm-Named Agent IDs** | 309 | 14 | **4.3%** |
| **CUDA: Non-Swarm Agent IDs** | 1,285 | 22 | **1.7%** |
| **CUDA Rig Aggregate** | 1,594 | 36 | **2.2%** |

On the Metal rig, work followed a sharp temporal shift. During the multi-agent review swarm (J1-J3 tracks), multiple agents audited identical code changes simultaneously, yielding a 12.0% deduplication rate. In contrast, during single-agent development, deduplication dropped to 0.8%.

On the CUDA rig, development operated under continuous concurrency (five to 23 active agents daily). Swarm-named task agents matched at 4.3%, whereas non-swarm agents matched at 1.7%. This telemetry is consistent with the hypothesis that write-time deduplication correlates with concurrent task overlap rather than store consolidation.

## 5.3 Model Verbal Drift and Concept Lengths

Payload length distributions across frontier language model families reveal a striking divergence:

| Model Group | Store | $n$ | Mean Length | Median (p50) | p90 | Share $>$500 B |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **Claude family** | CUDA | 620 | 325 B | 319 B | 706 B | **30.0%** |
| **GPT family** | CUDA | 319 | 152 B | 67 B | 433 B | **7.5%** |
| **Grok family** | CUDA | 204 | 144 B | 130 B | 302 B | **1.0%** |
| *CUDA Aggregate* | *CUDA* | *1,819* | *232 B* | *90 B* | *585 B* | *15.7%* |
| **Claude family** | Metal | 713 | 407 B | 356 B | 918 B | **38.7%** |
| **GPT family** | Metal | 43 | 196 B | 164 B | 395 B | **4.7%** |
| **Grok family** | Metal | 29 | 62 B | 44 B | 135 B | **0.0%** |
| *Metal Aggregate* | *Metal* | *889* | *392 B* | *315 B* | *932 B* | *35.9%* |

Across both stores, the Claude family generated verbose multi-sentence paragraphs (30% to 39% exceeding 500 bytes), whereas GPT and Grok agents generated concise atomic statements (fewer than 8% exceeding 500 bytes).

The model-family groups differ in task mix, prompting, and deployment conditions. Payload length alone does not establish a causal effect on retrieval errors.

## 5.4 Coordination Telemetry: Advisory Locks vs. Receipts

Early agent memory designs proposed distributed advisory locks via `lambo_reserve`. Production telemetry showed that agents rarely acquired advisory locks:
* On the Metal rig, **zero calls** were made to `lambo_reserve` across 247 writes.
* On the CUDA rig, only **27 of 422 writes (6.4%)** utilized soft locks. Twenty-two of those 27 calls came from a single agent (`gpt-5.6-terra`), and only 5 of 63 agents ever invoked reservations.

Discoverability and identifier fragmentation are possible explanations for low reservation use. Issue 8 reports a 0.1 ms median CUDA derive acknowledgement. Receipts report individual write outcomes; application and disk persistence are separate. The Metal window also includes earlier synchronous calls.

## 5.6 Preliminary Paired Comparison

The [Issue 17 report](https://github.com/nrynss/lambo/issues/17) described an anecdotal comparison against Claude Code file memory. It omitted the query set, prompts, model version, token budget, baseline construction, and grading protocol. A reproducible harness replaces it here. These results are preliminary.

We froze every context before producing any answer and fixed the rubrics from primary sources. One pinned reader answered every prompt, Claude Code 2.1.241 running `claude-sonnet-5` without tools or network memory. A separate model grader scored the answers blind, receiving shuffled answer identifiers and no arm key. Mode was as-deployed, with six questions and two repeats on each of two corpora drawn from the operator's open-source projects.

| Question | File | Lambo |
|---|---:|---:|
| *vimanam project* | | |
| merge-workflow | 2/2 | 2/2 |
| ci-clippy-failure | 2/2 | 2/2 |
| diff-design | 0/2 | 2/2 |
| packaging-decision | 2/2 | 0/2 |
| brand-org | 2/2 | 0/2 |
| abstention | 2/2 | 2/2 |
| **Total** | **10/12** | **8/12** |
| *lambo project* | | |
| **Total** | **8/12** | **2/12** |

Each system won exactly the questions only it had ingested. Lambo won the in-session design decision that never reached a curated note. File memory won two decisions taken before the store existed. Under the grader's stricter alternative readings, the vimanam run is 9/12 against 6/12.

Seven of the twelve questions have an answer-bearing concept in the store. Lambo's answers are present at depth 20 for 6 of 7 of those questions. They are present at depth 3 for only 4 of 7. The rendered context carried two or three hits, so readers saw the shallower figure. Readers were correct on 6 of 8 answers where that context covered the rubric. They were correct on 0 of 6 answers where it did not.

Canonization has never promoted a concept, so recall has no supersession signal. The embedder question came back stale twice, presenting a retired encoder as current. Two further answers repeated a stale hypothesis beside the correct mechanism. The readers invented no fact across 48 answers, and abstention accounted for every other failure.

In the vimanam run, Lambo used about a fifth of the evidence tokens per correct answer. That run spent 2,467 evidence tokens per correct file answer against 477 for Lambo. The lambo run spent 4,542 against 2,058. Server-side recall p50 was 86 to 94 ms over 990 concepts.

The repository publishes the suites, frozen bundles, answers, grades, and grader provenance under `evaluation/results/2026-09-07`.
