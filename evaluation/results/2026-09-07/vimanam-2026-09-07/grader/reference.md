## diff-design
Source: issue #45 design comment and PR #92 title.
```
## Design requirement: diff must operate on *resolved* schemas

A diff can compare specs at three levels, and each higher level is blind to drift the level below it catches:

1. **Path-set diff** — which `METHOD path` pairs were added/removed. Misses everything about shape.
2. **Operation-object diff** — byte/structural compare of each operation object. Still misses shape drift, because operations reference shapes by `$ref` — the pointer string is unchanged even when its target changes.
3. **Resolved-schema diff** — compare each operation's request/response shapes *after* inlining all `$ref`s. This is the only level that sees the truth.

### Why levels 1–2 are insufficient

The most common real-world drift is a **change behind a `$ref`**: a shared schema gains a field, tightens a required-ness, or changes a type. Every endpoint that references that schema now returns a different shape — but:

- its path is unchanged (path-set diff says "no change")
- its operation object is byte-identical, since it only holds `{"$ref": "#/components/schemas/Foo"}` (operation diff says "no change")
feat: diff subcommand comparing spec versions on resolved schemas (#45)
```
Fact: the diff compares RESOLVED schemas (after inlining all $refs), because path-set and operation-object diffs miss shape drift. Chosen design (option b): resolve $refs into serde_json::Value, canonicalise, then run a generic Value differ that reports JSON-pointer paths. Shipped as PR #92 (db42292) on 2026-09-05.
