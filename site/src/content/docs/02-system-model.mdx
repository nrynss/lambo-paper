## 2.1 Single-Writer Daemon Topology

The inspected deployment uses a local daemon that centralizes graph mutation. Agents communicate through Unix sockets or local HTTP streams. The operational window also includes earlier per-session stdio deployments, so this is an architectural description rather than a constant experimental condition.

## 2.2 Directed Typed Graph Model

Lambo represents software state as a directed typed multigraph $\mathcal{G} = (\mathcal{V}, \mathcal{E})$.

### Concept Nodes ($\mathcal{V}$)
Each concept node $c \in \mathcal{V}$ possesses a type classification $\tau(c) \in \mathcal{T}$:
* **Logic:** Structural invariants, algorithmic rules, and core protocol invariants.
* **Constraint:** Guard rails, version bounds, and operational ceilings.
* **Observation:** Empirical measurements, telemetry samples, and runtime logs.
* **Resource:** Artifact handles, API endpoints, schema definitions, and file paths.
* **Entity:** Stable named abstractions, actors, and subsystems.

### Typed Edges ($\mathcal{E}$)
Edges capture precise architectural semantics $\epsilon(e) \in \mathcal{R}$:
* **Dependency:** Upstream structural prerequisite ($u \to v$).
* **Causal:** Invariant $u$ was established as a direct consequence of $v$.
* **Hierarchical:** Parent-child grouping ($u$ contains $v$).
* **CoOccurrence:** Derived concurrently within interaction $i$.
* **Semantic:** High cosine similarity connection between text embeddings.
* **Provenance:** Audit link attributing $c$ to creating agent and interaction.

## 2.3 Level-B Storage Pluggability

Storage drivers are compiled as modular adapters behind a `GraphStore` trait. This report describes the inspected drivers and does not claim identical behavior across untested configurations.

Lambo ships a Postgres store adapter beside SQLite. Mooshik, an ambient local-first cowork partner ([github.com/nrynss/mooshik](https://github.com/nrynss/mooshik)), runs Lambo against a hosted Postgres store so that several machines share one memory.
