---
title: "3. 3-Phase Recall Engine"
description: "Hybrid candidate scoring, prioritized breadth-first expansion, and token assembly."
---

Lambo executes retrieval via a calibrated three-phase hybrid recall engine:

## Phase 1: Candidate Generation and Max-Merge

Given query $q$, candidate generation combines three orthogonal retrieval legs:
1. **Lexical Leg:** Inverted BM25 keyword index matching.
2. **Dense Vector Leg:** Exact cosine similarity over dense vector embeddings (BGE-M3 1024-dim).
3. **Recency Leg:** Temporal recency bias over recently touched concepts.

Phase 1 max-merges raw leg scores:
$$S_1(q, c) = \max\left( S_{\text{lex}}(q, c), \quad S_{\text{vec}}(q, c), \quad S_{\text{rec}}(c) \right)$$

The implementation returns the over-fetched union without Phase-1 top-$K$ truncation. Final selection occurs during assembly. Raw BM25, cosine, and recency values are not normalized, so this is a heuristic whose cross-leg scale effects need ablation.

## Phase 2: Prioritized Breadth-First Expansion

The candidate set forms seeds for graph traversal up to depth $D_{\max} = 2$. At each frontier node, traversal follows edges according to strict priority:
$$\text{Dependency} \succ \text{Causal} \succ \text{Hierarchical} \succ \text{CoOccurrence} \succ \text{Semantic}$$

Concepts sharing a `chunk_group_id` with an expanded node are force-included as siblings.

## Phase 3: Composite Scoring and Token Assembly

Expanded concepts are evaluated using composite daemon scoring. The inspected default uses equal 0.5 weights, although frozen telemetry does not retain a complete historical configuration:
$$S_{\text{final}}(c) = 0.5 \cdot S_{\text{daemon}}(c) + 0.5 \cdot S_1(q, c)$$

The daemon score incorporates topological health, access frequency, recency, degree density, edge bonuses, and type modifiers. Warnings are rendered separately from budgeted context blocks, so a dropped block may still contribute a warning.
