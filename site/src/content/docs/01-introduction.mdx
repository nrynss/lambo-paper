Autonomous software engineering agents increasingly collaborate in swarms. Modern workflows deploy concurrent agents to refactor code, run tests, and remediate review findings. However, each agent invocation is fundamentally ephemeral. When an agent session terminates, its internal reasoning context disappears. Subsequent agents must re-derive architectural decisions from scratch.

## Limitations of Existing Paradigms

Existing memory paradigms fail to maintain coherent state in software engineering projects:
* **Flat markdown scratchpads** lack structural relationships. They cannot express multi-hop dependency chains or track invalidated decisions.
* **Flat vector retrieval stores** (RAG, MemoryBank) evaluate pairwise cosine similarity between query text and isolated text chunks. In technical codebases, flat vector search suffers from semantic drift: it fails to distinguish between active constraints and superseded implementations.
* **Graph retrieval frameworks** (GraphRAG, HippoRAG) address graph-based retrieval in different document workloads. This report does not infer that they cannot support continuous mutation.

## The Lambo Approach

To resolve these challenges, we present **Lambo**. Lambo is an in-memory topological memory daemon designed for multi-agent development. Lambo runs as a local supervised daemon exposing a Model Context Protocol (MCP) interface. Agents record typed architectural concepts and directed relationships during execution. Concepts represent logic invariants, structural constraints, and runtime observations.

Lambo uses a local daemon with per-agent FIFO admission lanes for qualifying asynchronous operations. `derive` and `record_action` receive composite receipt IDs, which a caller can query for individual applied or pending state. `reserve` remains synchronous. The report distinguishes applied receipt state from write-behind persistence.
