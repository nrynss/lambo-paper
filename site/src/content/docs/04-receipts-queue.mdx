description: "Non-blocking mutation ingestion, monotonic receipt ordering, and barrier synchronization."

## Asynchronous Write Queue

Lambo completely decouples agent MCP tool invocations from database transactions. When an agent calls `lambo_derive` or `lambo_record_action`:
1. The mutation payload enters an in-memory bounded queue (`Crossbeam`).
2. The daemon dispatches a monotonically increasing 64-bit integer receipt $r \in \mathbb{N}$.
3. The MCP call returns immediately with receipt $r$ in sub-millisecond time ($0.1$ ms median).

## Barrier Synchronization

When subsequent agent steps depend on committed state, agents check receipt barriers:
* An agent queries `lambo_stats` to verify that the daemon's applied receipt sequence has reached or exceeded $r$.
* This guarantees read-your-writes consistency without requiring synchronous distributed database locks.
