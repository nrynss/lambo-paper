## Asynchronous Write Queue

For `lambo_derive` and `lambo_record_action`, validation and interaction opening occur on the call path. An accepted background job receives a composite receipt ID containing epoch, time, and sequence fields. Receipt numbers are assigned before lane admission, so numeric order is not global drain order. Each agent has a FIFO lane for sequential submissions, while different lanes may run concurrently. `lambo_reserve` stays synchronous.

## Barrier Synchronization

When subsequent steps depend on applied state, agents check individual receipts:
* An agent queries a specific receipt through `lambo_stats` when it needs an applied, failed, pending, or replay-related state.
* Applied records graph-path completion. Write-behind persistence and clean-close durable intents are separate boundaries.
