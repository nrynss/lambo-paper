\begin{abstract}
Autonomous coding agents operate within ephemeral process lifecycles.
When agents complete execution, their intermediate reasoning and architectural context vanish.
Similarity retrieval alone does not explicitly encode dependency or invalidation relationships.
We present Lambo, an in-memory topological memory daemon for multi-agent software engineering.
Lambo models development state as a directed typed graph with an earned canonization lifecycle.
Concurrent agents submit asynchronous writes through per-agent lanes with individual receipt states.
Context retrieval uses three-leg hybrid candidate scoring and prioritized breadth-first topological expansion.
Phase one merges lexical, recency, and dense vector signals.
Phase two traverses structural dependency edges while respecting invalidation semantics.
Phase three enforces canonical-first ranking and hot-list conflict preservation under token budgets.
We report operational telemetry from two production rigs using nominal 5-minute health sampling.
The extract contains 2,495 CUDA and 3,429 Metal heartbeat snapshots. At the nominal interval, those counts correspond to 8.7 and 11.9 interval-equivalent days within 12.7 and 16.0 day windows.
Deduplication rates reached 12.0\% during synchronized review swarms on Metal (against 0.8\% in single-agent sessions) and 4.3\% among swarm-named agents on CUDA (against 1.7\% in non-swarm streams, 2.2\% aggregate).
The tracked infrastructure counters were zero in this extract, which does not establish zero failures or data loss.
CUDA inspect misses were 22 of 82, while Metal had one miss in four calls and is too small for a cross-rig rate comparison.
No concepts reached Canonical status, and the observed Metal store had no concepts eligible for the first promotion gate.
A preliminary paired comparison against Claude Code file memory scored 10/12 for file memory against 8/12 for Lambo on one corpus, and 8/12 against 2/12 on a second.
We discuss citation dilution as a separate hypothesis and identify controlled retrieval evaluation as future work.
\end{abstract}

\section{Introduction}

Autonomous software engineering agents increasingly collaborate in swarms.
Modern workflows deploy concurrent agents to refactor code, run tests, and remediate review findings.
However, each agent invocation is fundamentally ephemeral.
When an agent session terminates, its internal reasoning context disappears.
Subsequent agents must re-derive architectural decisions from scratch.

Maintaining coherent development context requires representing both decisions and their revisions.
Flat markdown scratchpads and vector stores make different tradeoffs in representing relationships and supersession.
Flat vector retrieval stores \cite{lewis2020rag, zhong2023memorybank, xiao2024survey} commonly rank text chunks with similarity signals.
This daemon explores explicit typed edges for codebase constraints and invalidation context.
Graph retrieval frameworks \cite{edge2024graphrag, gutierrez2024hipporag} emphasize graph-based retrieval over document collections.
Lambo focuses on agent-written development state and local mutation handling.

To resolve these challenges, we present Lambo.
Lambo is an in-memory topological memory daemon designed for multi-agent development.
Lambo runs as a local supervised daemon exposing a Model Context Protocol (MCP) interface.
Agents record typed architectural concepts and directed relationships during execution.
Concepts represent logic invariants, structural constraints, and runtime observations.

Lambo uses per-agent admission lanes for asynchronous \texttt{derive} and \texttt{record\_action} work.
These calls receive composite receipt identifiers and may be awaited by identifier when an agent needs applied state.
Retrieval operates via a three-phase hybrid topological pipeline.
Phase one computes the maximum merge across keyword, recency, and dense vector candidates.
Phase two performs prioritized breadth-first search across architectural dependency edges.
Phase three applies daemon composite scoring, hot-list conflict preservation, and canonical-first ordering.

We report a systems experience across discrete GPU and unified-memory rigs.
The nominal windows are 12.7 and 16.0 days, with 8.7 and 11.9 interval-equivalent days of snapshots.
The extract contains zero values for selected counters, observed deduplication regimes, and model-family content-length differences that are confounded by task and model mix.
These observations motivate improvements to retrieval evaluation, promotion eligibility, and tool interfaces.

\section{System Architecture and Invariants}

\subsection{Single-Writer Daemon Topology}
Figure \ref{fig:arch} illustrates the system architecture of Lambo.
Lambo enforces a single-writer daemon topology.
One supervised background daemon holds exclusive write authority over a durable session.
Agents communicate with the daemon via Unix domain sockets or local HTTP streams.
The design centralizes graph mutation in one daemon process while other callers may issue concurrent reads.

\subsection{Asynchronous Write Queue and Receipts}
\texttt{derive} and \texttt{record\_action} may acknowledge after admission while embedding and insertion continue in the background. \texttt{reserve} remains synchronous because its result gates the caller's next action.
Each admitted job receives a composite receipt identifier containing an epoch, time, and sequence component. Receipt numbers are assigned before lane admission, so their numeric order is not a global drain or commit order.
Each agent has a FIFO admission lane for sequential submissions, while lanes from different agents may run concurrently. A caller can query an individual receipt for an applied, failed, pending, or replay-related state. An applied receipt records ordinary graph-path completion. It does not itself assert that a disk flush has completed.
The inspected implementation uses write-behind persistence and durable intents at clean close. This report therefore separates application state from the persistence boundary.

\begin{algorithm}[t]
\caption{Asynchronous Ingestion and Receipt Scheduling}
\label{alg:ingest}
\small
\begin{algorithmic}[1]
\Require Queue $\mathcal{Q}_{\text{in}}$, In-Memory Graph $\mathcal{G}$, Persistent Store $\mathcal{S}$
\Ensure Per-job receipt state and per-agent FIFO admission
\Function{SubmitAsync}{$m, \text{agent\_id}$}
    \State Validate and open the interaction synchronously
    \State $r \gets \text{CompositeReceipt}(\text{epoch}, \text{time}, \text{sequence})$
    \State Check admission bounds under graph and lane locks
    \State Refuse admission if the lane or queue is full
    \State Record an intent in the write-behind log and enqueue $\text{Job}(r,m)$
    \State \Return $r$
\EndFunction
\Statex
\Function{AgentLaneWorker}{$\text{agent\_id}$}
    \While{$\text{DaemonIsRunning}()$}
        \State Dequeue the next job from this agent's lane
        \State Embed and apply the job through the ordinary graph path
        \State Set its receipt to \textsc{Applied} or \textsc{Failed}
        \State Write-behind persistence flushes separately from receipt application
    \EndWhile
\EndFunction
\end{algorithmic}
\end{algorithm}

\subsection{Level-B Storage Pluggability}
Lambo implements Level-B storage pluggability via compile-time Cargo feature flags.
The core graph engine accesses persistence through a shared storage interface.
Supported engines include embedded SQLite, PostgreSQL, and CockroachDB.
Adapters implement the same storage contract while retaining backend-specific transaction and vector-search implementations.
The deployment evaluation reported here uses SQLite on both rigs.

\subsection{The Embedding Contract Invariant}
Vector spaces are fragile under encoder model migrations.
Comparing vector embeddings generated by divergent models corrupts metric spaces.
Lambo enforces an immutable session-level embedding contract.
The contract is defined by a three-tuple:
\begin{equation}
\mathcal{C} = (\kappa, \mu, d)
\end{equation}
Here, $\kappa$ identifies the provider, $\mu$ defines the model name, and $d$ specifies the exact vector dimensionality.
The storage engine records $\mathcal{C}$ at session initialization.
Any subsequent process that attaches with a mismatched contract is rejected immediately.
The check prevents mixing incompatible declared embedding configurations within a session.

\section{Formal Memory Model}

\subsection{The Directed Attributed Multi-Graph}
Lambo models development state as a directed, attributed multi-graph:
\begin{equation}
\mathcal{G} = (\mathcal{V}, \mathcal{E})
\end{equation}
The node set $\mathcal{V}$ represents typed concepts.
Each concept node $c \in \mathcal{V}$ possesses a type classification:
\begin{align}
\tau(c) \in \{&\text{Logic}, \text{Constraint}, \text{Observation}, \nonumber \\
              &\text{Entity}, \text{Resource}\}
\end{align}
Each node maintains a text payload, creation timestamp $t_c$, access counter $\alpha_c$, and dense embedding $\mathbf{e}_c \in \mathbb{R}^d$.

Edges in $\mathcal{E}$ represent typed architectural dependencies:
\begin{align}
\epsilon(e) \in \{&\text{Dependency}, \text{Causal}, \text{Hierarchical}, \nonumber \\
                  &\text{CoOccurrence}, \text{Semantic}\}
\end{align}
In addition, bipartite provenance edges track agent actions.
These include \textbf{Derives} edges from interactions to concepts and \textbf{Temporal} ordering edges. Invalidation is represented by edge polarity rather than a separate \textbf{Invalidates} edge type.

\subsection{Three-Leg Hybrid Candidate Retrieval}
Given a natural language query $q$, the recall engine retrieves candidate nodes from three orthogonal legs.
First, the lexical leg evaluates term frequencies over an inverted text index using BM25 \cite{robertson2009bm25}.
\begin{equation}
S_{\text{lex}}(q, c) = \text{BM25}(q, c)
\end{equation}
To prevent lexical candidates from being evicted by flat scores, the lexical search over-fetches with multiplier $M = 4$.

Second, the recency leg retrieves concepts derived within the $N_{\text{recent}} = 3$ most recent interactions.
Lambo assigns these candidates a fixed recency score.
Members of this leg receive a flat floor score:
\begin{equation}
S_{\text{rec}}(c) = \rho_{\text{floor}} = 0.35
\end{equation}
An internal calibration using BGE-M3 \cite{chen2024bge} contained a 0.3991 true-recall score.
The \href{https://github.com/nrynss/lambo/tree/e11fb06ba61a480c8400d89ad6e40bbc39fc46c0/evidence/mooshik-g-recall-calibration}{calibration artifact} documents this fixture-specific observation and the floor adjustment.
Setting $\rho_{\text{floor}} = 0.35$ is an implementation heuristic whose interaction with raw BM25 and cosine scales needs evaluation.

Third, the vector leg projects query text into vector $\mathbf{e}_q \in \mathbb{R}^d$ and computes cosine similarity.
\begin{equation}
S_{\text{vec}}(q, c) = \cos(\mathbf{e}_q, \mathbf{e}_c) = \frac{\mathbf{e}_q \cdot \mathbf{e}_c}{\|\mathbf{e}_q\|_2 \|\mathbf{e}_c\|_2}
\end{equation}

Phase one merges candidate scores using a maximum selection rule.
\begin{equation}
S_1(q, c) = \max\left( S_{\text{lex}}(q, c), \quad S_{\text{vec}}(q, c), \quad S_{\text{rec}}(c) \right)
\end{equation}
The implementation returns the over-fetched union without Phase-1 top-$K$ truncation. Final selection occurs downstream during Phase-3 assembly. Because BM25, cosine similarity, and the recency floor are max-merged without normalization, this is a heuristic candidate score whose cross-leg scale effects require controlled ablation.

\subsection{Phase-2 Prioritized Breadth-First Expansion}
The candidate set forms the frontier for Phase-2 graph traversal.
Unlike Personalized PageRank in HippoRAG \cite{gutierrez2024hipporag, gutierrez2025hipporag2}, Lambo prioritizes directed architectural edges.
Starting from Phase-1 seeds at depth zero, Lambo executes a breadth-first search up to depth $D_{\max} = 2$.
At each frontier node, traversal follows edges according to strict type priority:
\begin{align}
\text{Dependency} &\succ \text{Causal} \succ \text{Hierarchical} \nonumber \\
                  &\succ \text{CoOccurrence} \succ \text{Semantic}
\end{align}
Provenance edges are excluded from Phase-2 expansion.
A visited set cycle guard ensures that each concept is enqueued at most once.
The earliest discovery path defines node membership.

Furthermore, Lambo applies a transitive closure over chunk grouping identifiers.
Concepts sharing a $\mathtt{chunk\_group\_id}$ with an expanded node are force-included as siblings.
Phase-1 candidates retain their $S_1$ scores, whereas newly expanded neighbors enter Phase 3 with an initial score of zero.

\subsection{Phase-3 Composite Scoring and Token Assembly}
Phase three computes final composite scores for all expanded concepts:
\begin{equation}
S_{\text{final}}(c) = w_{\text{daemon}} \cdot S_{\text{daemon}}(c) + w_{\text{query}} \cdot S_1(q, c)
\end{equation}
In the inspected default configuration, $w_{\text{daemon}} = 0.5$ and $w_{\text{query}} = 0.5$. The frozen telemetry does not retain a complete configuration record.
The daemon score $S_{\text{daemon}}(c) \in [0, 1 + B_{\max}]$ evaluates session-relative topological health:
\begin{align}
S_{\text{daemon}}(c) &= 0.25 \cdot R(c) + 0.20 \cdot F(c) + 0.20 \cdot A(c) \nonumber \\
&+ 0.35 \cdot \Delta(c) + \beta_{\text{edge}}(c) + \mu_{\text{type}}(\tau(c))
\end{align}
The normalized component metrics are defined as follows:
\begin{itemize}
    \item \textbf{Recency:} $R(c) = \frac{t_{\text{touch}}(c) - t_{\text{start}}}{t_{\text{end}} - t_{\text{start}}}$, normalized over session duration.
    \item \textbf{Frequency:} $F(c) = \min\left(1.0, \frac{\alpha_c}{10.0}\right)$, saturating at ten accesses.
    \item \textbf{Session Activity:} $A(c) = \frac{|\{i \in \mathcal{I} \mid i \xrightarrow{\text{Derives}} c\}|}{|\mathcal{I}|}$.
    \item \textbf{Graph Density:} $\Delta(c) = \frac{\text{deg}(c)}{\max_{u \in \mathcal{V}} \text{deg}(u)}$, scaled by maximum degree.
    \item \textbf{Edge Bonus:} $\beta_{\text{edge}}(c) = \min\left(0.25, \sum_{e \sim c} b(\epsilon(e))\right)$.
    \item \textbf{Type Modifier:} $\mu_{\text{type}}(\text{Constraint}) = +0.15$, $\mu_{\text{type}}(\text{Entity}) = +0.05$, $\mu_{\text{type}}(\text{Logic}) = +0.05$, $\mu_{\text{type}}(\text{Resource}) = 0.0$, and $\mu_{\text{type}}(\text{Observation}) = -0.10$.
\end{itemize}

Each weighted component is clamped to $[0,1]$, and the composite is clamped to $[0,1.4]$ under these default weights.
A zero-duration recency extent yields one. Empty interaction or degree denominators yield zero.
The Metal deployment report records zero access counters, so the frequency term supplied no recall-usage signal in that store.

\subsection{Canonical-First Ordering and Token Budgets}
Hits are sorted by canonical priority and final score:
\begin{equation}
\text{RankKey}(c) = (\mathbb{I}_{\text{canonical}}(c), \quad S_{\text{final}}(c), \quad -\text{NodeId}(c))
\end{equation}
Here, $\mathbb{I}_{\text{canonical}}(c) \in \{0, 1\}$ guarantees that Canonical concepts appear ahead of non-canonical concepts.
Active conflict warnings are rendered separately from budgeted context blocks. A block dropped by the token budget can still contribute a warning.
Text context is assembled from a score-ordered prefix of whole concept blocks that fits within token budget $T_{\max}$.
Algorithm \ref{alg:recall} formalizes this complete retrieval workflow.

\begin{algorithm}[t]
\caption{Three-Phase Topological Recall (Simplified)}
\label{alg:recall}
\small
\begin{algorithmic}[1]
\Require Query string $q$, Graph $\mathcal{G}$, Inverted Index $\mathcal{I}$, Limit $K$, Depth $D_{\max}$
\Ensure Budgeted context and separately rendered warnings
\State $\mathcal{C}_{\text{lex}} \gets \mathcal{I}.\text{Search}(q, K \times 4)$
\State $\mathcal{C}_{\text{rec}} \gets \{c \in \mathcal{V} \mid c \text{ from } 3 \text{ most recent interactions}\}$
\State $\mathbf{e}_q \gets \text{Embedder}.\text{Embed}(q)$
\State $\mathcal{C}_{\text{vec}} \gets \text{VectorSearch}(\mathbf{e}_q, K)$
\State $\mathcal{C}_1 \gets \emptyset$
\For{$c \in \mathcal{C}_{\text{lex}} \cup \mathcal{C}_{\text{rec}} \cup \mathcal{C}_{\text{vec}}$}
    \State $s \gets \max(S_{\text{lex}}(q,c), \quad S_{\text{vec}}(q,c), \quad S_{\text{rec}}(c))$
    \State $\mathcal{C}_1 \gets \mathcal{C}_1 \cup \{(c, s)\}$
\EndFor
\State $\mathcal{S}_{\text{seeds}} \gets \text{RankedUnion}(\mathcal{C}_1)$ \Comment{unreduced candidate over-approximation}
\State $\mathcal{V}_{\text{bfs}} \gets \mathcal{S}_{\text{seeds}}$
\State $\mathcal{Q} \gets \text{Queue}((c,0) \mid c \in \mathcal{S}_{\text{seeds}})$
\State $\text{Visited} \gets \text{Set}(\mathcal{S}_{\text{seeds}})$
\While{$\mathcal{Q} \neq \emptyset$}
    \State $(u,d) \gets \mathcal{Q}.\text{Pop}()$
    \If{$d \ge D_{\max}$} \State \textbf{continue} \EndIf
    \For{$e \in \text{SortedEdges}(u.\text{OutEdges})$}
        \State $v \gets e.\text{Target}$
        \If{$v \notin \text{Visited}$ and $\epsilon(e) \in \text{TraversableTypes}$}
            \State $\text{Visited}.\text{Add}(v)$
            \State $\mathcal{V}_{\text{bfs}} \gets \mathcal{V}_{\text{bfs}} \cup \{(v, 0.0)\}$
            \State $\mathcal{Q}.\text{Push}((v,d+1))$
        \EndIf
    \EndFor
\EndWhile
\State $\mathcal{V}_{\text{all}} \gets \mathcal{V}_{\text{bfs}} \cup \text{ChunkGroupSiblings}(\mathcal{V}_{\text{bfs}})$
\For{$c \in \mathcal{V}_{\text{all}}$}
    \State $S_{\text{final}}(c) \gets 0.5 \cdot S_{\text{daemon}}(c) + 0.5 \cdot S_1(q, c)$
\EndFor
\State $\mathcal{H}_{\text{sorted}} \gets \text{SortByCanonicalAndScore}(\mathcal{V}_{\text{all}})$
\State $\mathcal{H} \gets \text{TopKPlusRevalidatedHotMembers}(\mathcal{H}_{\text{sorted}}, K)$
\State $\mathcal{W} \gets \text{Warnings}(\mathcal{H})$
\State $\text{context} \gets \text{WholeBlockPrefix}(\mathcal{H}, T_{\max})$
\State \Return $(\text{context},\mathcal{W})$
\end{algorithmic}
\end{algorithm}

\section{The Promotion Engine and Lifecycle}

\subsection{The Three-Stage Canonization Pipeline}
The daemon executes periodic background canonization evaluations.
Concepts transition across three formal lifecycle states:
\begin{equation}
\text{Candidate} \xrightarrow{\text{Stage 1, 2}} \text{Venerable} \xrightarrow{\text{Stage 3}} \text{Canonical}
\end{equation}
While Voyager \cite{wang2023voyager} accumulates executable skills and Reflexion \cite{shinn2023reflexion} relies on verbal reflection, Lambo enforces earned canonization through topological gates.
Promotion requires passing four orthogonal evidence gates.
Stage one evaluates the garbage collection survival count.
\begin{equation}
\text{gc\_survived}(c) \ge 3
\end{equation}
Stage two checks for derivation across distinct interactions.
\begin{equation}
\text{distinct\_interactions}(c) \ge 3
\end{equation}
Stage two also requires structural edge coverage over session time.
\begin{equation}
\text{coverage}(c) = \frac{\max(t) - \min(t)}{t_{\text{extent}}} \ge 0.30
\end{equation}
Stage three requires a verified blast radius strictly exceeding five.
\begin{equation}
\text{blast\_radius}(c) > 5
\end{equation}

\subsection{Consensus Promotion Policies}
Lambo supports two alternative promotion scorers:
\begin{itemize}
    \item \textbf{Solo Policy:} Focuses on longitudinal recurrence within single-developer workflows.
    It evaluates time-separated session counts without checking peer agent consensus.
    \item \textbf{Swarm Policy:} Enforces multi-agent consensus.
    Promotion requires concurrent corroboration across independent agent identities.
\end{itemize}

\subsection{The Multi-Repository Dispersion Formulation}
The \href{https://github.com/nrynss/lambo/issues/17}{Metal operational report} records approximately 15,000 canonization cycles with zero Swarm-policy Canonical concepts.
It also records \texttt{gc\_survived}=0 for every concept, so the first gate, \texttt{gc\_survived} $\ge 3$, already blocked promotion.
This count cannot be attributed to repository dispersion. It is a workload and gate-state observation, not evidence that promotion permanently freezes or that namespace scoping supplies sufficient corroboration.
We use the term \textit{Multi-Repository Dispersion Hypothesis} for the following simplified model.

Let $M$ denote the total interaction volume generated by an agent swarm.
Assume an operator works across $R$ independent repositories.
The total concept space partitions into $R$ disconnected subgraphs:
\begin{equation}
\mathcal{G} = \bigcup_{r=1}^R \mathcal{G}_r, \quad \mathcal{G}_i \cap \mathcal{G}_j = \emptyset \quad \forall i \neq j
\end{equation}

Assuming uniform interaction distribution across repositories, the expected interactions per repository equals:
\begin{equation}
\mathbb{E}[M_r] = \frac{M}{R}
\end{equation}

Let $\delta_r(c)$ denote the citation count for concept $c$ over a fixed observation window.
Assume the probability of citing $c$ per interaction within its repository stays constant as $R$ changes.
Under these assumptions, the expected count scales inversely with repository count:
\begin{equation}
\mathbb{E}[\delta_r(c)] = \frac{\delta_{\text{base}}(c)}{R}
\end{equation}
Figure \ref{fig:dispersion} depicts this relationship.
For a fixed baseline citation density, the model reduces the expected local density by a factor of $R$.
Citations may be diluted across disjoint problem domains under these assumptions.
The derivation does not model task distributions, cross-repository concepts, gate-level eligibility, or agent behavior. It therefore motivates a future evaluation of promotion gates and namespace policies rather than prescribing a universal policy.

\subsection{Telemetry and Infrastructure Reliability}
Table \ref{tab:reliability} summarizes automated telemetry over the multi-rig evaluation.
The frozen extracts contain 2,495 CUDA and 3,429 Metal heartbeat snapshots. At the nominal five-minute interval, those are 8.7 and 11.9 interval-equivalent days, whereas the monitoring windows are 12.7 and 16.0 days. They do not measure uptime or continuous coverage.
Every listed infrastructure counter is zero in these samples. These counters do not demonstrate zero daemon failures, restarts, or data loss outside their coverage. The 52 CUDA and 12 Metal process restarts require separate causal and recovery evidence.

In contrast to infrastructure health, tool execution telemetry revealed application-level failures.
Across 1,020 tool calls on the CUDA rig, 25 calls returned errors.
Twenty-two errors were \texttt{lambo\_inspect} misses on approximate strings, and three were invalid reservation arguments.
On the Metal rig, four inspect calls produced one miss. This denominator is too small to estimate a stable cross-rig rate.
The CUDA misses are consistent with an affordance gap, but the dataset does not establish its cause.
The \texttt{lambo\_recall} tool renders text content without unique node identifiers.
Approximate-string inspect calls suggest that explicit handles could improve tool use.

\subsection{Model Verbal Drift and Concept Lengths}
Table \ref{tab:length} presents concept payload lengths across frontier language model families.
Both stores show differences in payload length among the recorded model-family groups.
Across both platforms, the Claude family generated verbose multi-sentence paragraphs.
On CUDA, Claude median concept length was 319 bytes, with 30.0\% of concepts exceeding 500 bytes.
On Metal, Claude concepts averaged 407 bytes, with 38.7\% exceeding 500 bytes.
Reasoning concepts for Logic and Constraint reached mean lengths of 703 bytes and 707 bytes.
Conversely, GPT and Grok agents generated concise atomic statements.
On CUDA, GPT median length was 67 bytes, with only 7.5\% exceeding 500 bytes.
Grok concepts averaged 144 bytes on CUDA and 62 bytes on Metal.

The family labels are confounded with task mix, prompting, and deployment conditions. The telemetry does not identify a causal effect of length on false positives or show that graph topology mitigates one.

\subsection{Coordination Telemetry: Advisory Locks vs. Receipts}
Early agent memory designs proposed distributed advisory locks via $\mathtt{lambo\_reserve}$.
Under that proposal, agents acquire temporary reservations before editing shared code.
Our production telemetry demonstrated that agents rarely acquired advisory locks.
Across 247 writes on the Metal rig, zero calls were made to $\mathtt{lambo\_reserve}$.
On the CUDA rig, only 27 of 422 writes (6.4\%) utilized soft locks.
Furthermore, 22 of those 27 calls originated from a single agent.
Only five of 63 distinct agents ever invoked reservations.
Discoverability and identifier fragmentation are possible explanations for this low adoption.
Ephemeral agent identifiers make lease coordination difficult to maintain across sessions.
Instead, agents used asynchronous receipt-bearing writes.
Issue 8 reports a 0.1 ms median CUDA derive acknowledgement. The Metal window also contains earlier synchronous calls.
This allows agents to proceed without synchronous blocking.

\section{Systems Overheads and Hardware Analysis}

\subsection{The Vector Deserialization Bottleneck}
Figure \ref{fig:latency} reports end-to-end recall p50 rather than an isolated Phase-1 vector scan. CUDA observations were 16.8 ms at 100 concepts and 130.1 ms at 1,500 concepts. Metal observations were 24.0 ms at 100, 43.7 ms at 400, and 71.0 ms at 837 concepts.
The \href{https://github.com/nrynss/lambo/issues/8}{Issue 8 probe report} describes isolated store copies with embeddings retained on only $n$ concepts.
CUDA used 12 timed recalls per size after two warmups. Metal used 24 timed recalls per size, twelve distinct queries, and two warmups.
The following linear fits summarize those observations:
\begin{equation}
T_{\text{CUDA}}(n) = 8.7\,\text{ms} + 81\,\mu\text{s} \times n
\end{equation}
\begin{equation}
T_{\text{Metal}}(n) = 17.6\,\text{ms} + 64\,\mu\text{s} \times n
\end{equation}
Profiling identified the primary bottleneck in text deserialization.
The initial SQLite storage schema serialized dense vectors as decimal JSON arrays.
At 1,500 concepts, a CUDA recall query parsed approximately 19.1 MB of decimal strings.
This triggered 1,540,000 invocations of floating-point string parsers per query.
The report attributes approximately 87\% of recall time to the scan using the size-sweep slope and fixed-cost estimate.

Packed binary BLOB storage is a proposed optimization. The 20 to 30 ms range is a design target and has not been measured, so the report makes no slope, floor, or achieved-latency claim for it.

\subsection{Unified Memory Operating System Compression}
On the Apple Silicon Metal platform, we discovered a hardware-specific latency degradation.
When the Lambo daemon remained idle for extended intervals, macOS compressed idle process pages.
Out of a 1,429 MB process footprint, the memory manager compressed 1,417 MB.
The process-level compression observation does not identify which individual allocations were compressed.

In the recorded idle-duration bins, recall latency varied as follows:
\begin{itemize}
    \item \textbf{$<$2 minutes idle:} Recall latency p50 was 186 ms.
    \item \textbf{10 to 30 minutes idle:} Recall latency p50 rose to 567 ms.
    \item \textbf{$>$30 minutes idle:} Recall latency p50 reached 780 ms, with p90 reaching 9,059 ms.
\end{itemize}
These bins contain 19, 9, and 17 observations respectively and do not establish a causal operating-system mechanism. Periodic lightweight touches are a proposed mitigation that needs an intervention study.

\section{Limitations and Open Problems}

The paired comparison names two open problems in the deployed design.
First, the rendered context budget carries two or three hits, so it cuts off answers the store already holds. Six of seven answerable questions had an answer-bearing concept within depth 20, and only four were reachable at depth 3. Widening that budget or exporting the structured hits would separate ranking from rendering.
Second, recall carries no supersession signal. No concept has ever reached Canonical status, and no invalidation edge marked the superseded encoder concepts. The reader therefore presented a retired embedder as current in both repeats of that question.
These are two runs on one machine. They support no significance claim. The matched-corpus and equal-budget controls have not been run.

\section{Related Work}

\textbf{LLM Agent Memory.}
Seminal architectures established linear episodic memory streams \cite{park2023generative}.
Reflexion and Voyager explored iterative skill accumulation and verbal reinforcement learning \cite{shinn2023reflexion, wang2023voyager}.
MemoryBank introduced forgetting curves inspired by psychological theories \cite{zhong2023memorybank}.
These systems explore different memory representations and update policies. Lambo contributes a typed graph and promotion gates for a local multi-agent daemon.

\textbf{Graph Retrieval Architectures.}
GraphRAG and HippoRAG use graph representations for retrieval \cite{edge2024graphrag, gutierrez2024hipporag}.
HippoRAG uses Personalized PageRank and GraphRAG builds graph summaries over corpora. Lambo targets typed development constraints updated during agent execution.

\textbf{Agent Operating Systems and Shared Memory.}
MemGPT explored hierarchical memory paging for extended contexts \cite{packer2023memgpt}.
A-MEM dynamically organizes linked memories, while Collaborative Memory addresses multi-user sharing and access control \cite{xu2025amem, zhang2025collaborative}.
MemClaw formulated governed shared memory for agent fleets \cite{memclaw2026governed}.
Lambo contributes a local single-writer daemon architecture with per-agent FIFO admission lanes for qualifying asynchronous operations.

\section{Conclusion}

This systems experience documents a typed graph daemon, receipt-bearing asynchronous operations, and frozen operational telemetry.
The extracts contain 5,924 heartbeat snapshots and zero values for selected counters, but do not prove absence of failures or data loss.
Write-time deduplication was 12.0\% in one Metal review-swarm window and 4.3\% for CUDA swarm-named agent IDs.
The inverse-$R$ model is a hypothesis motivating controlled study of promotion gates and namespace policies.
Future evaluation should hold memories, reader model, prompts, and token budgets constant, compare flat and graph baselines, and ablate graph expansion and invalidation handling.
